# Architecture

## System Overview

The PGAI Voice Bot is a Python-based automated caller that uses **Vapi.ai** as its telephony and voice orchestration layer. When a scenario is triggered, `main.py` makes a single REST call to the Vapi API to initiate an outbound phone call from a rented US number to the PGAI test line (+1-805-439-8008). Vapi handles everything inside the call: it connects to the line, runs a **Deepgram** speech-to-text engine to transcribe what the agent says, feeds that into **OpenAI GPT-4o-mini** with a scenario-specific patient system prompt to generate a natural response, and then speaks that response using **OpenAI's Onyx TTS voice**. The result is a fully autonomous, turn-taking voice conversation that sounds and behaves like a real patient. When the conversation goal is achieved or an end-call phrase is detected, Vapi terminates the call and returns the transcript and recording URL, which `main.py` downloads and saves locally.

## Why Vapi Instead of Rolling My Own

The alternative was a custom Twilio stack: a Flask server, ngrok tunnel, WebSocket audio streaming, manual Deepgram integration, and custom turn-taking logic — roughly 600+ lines of infrastructure code before writing a single scenario. Vapi abstracts all of this into a single API call. The trade-off is less control over the exact audio pipeline, but for this challenge the priority is coherent, natural voice conversations at scale, not infrastructure complexity. Vapi's built-in endpointing (detecting when the agent has stopped speaking) produces better turn-taking behavior out of the box than a custom silence-detection implementation would in a short time window. GPT-4o-mini was chosen over GPT-4o for speed — lower latency means less awkward pauses in the conversation — while still producing fluent, realistic patient dialogue. The scenario system is deliberately data-driven (a list of dicts in `scenarios.py`) so new test cases can be added in under a minute without touching any logic code.
